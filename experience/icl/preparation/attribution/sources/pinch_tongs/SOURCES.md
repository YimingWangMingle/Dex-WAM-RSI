No hosted web research, external websites, papers, third-party datasets, other agents or other learned models were used. No benchmark solutions, evaluator code, privileged scene state, hidden seeds, test results or future episodes were accessed. There are no externally acquired benchmark facts to disclose.

The preparation used these task-provided sources:

- **Task specification, `input/task.json`:** `pinch_tongs`, prompt “Grasp the tongs and perform three consecutive open-close motions,” 100 released demonstrations, `rand_full`, single arm, 30 Hz, action/state layouts, and base/wrist camera mapping. The relevant contract is restated in TASK.md and index.json.
- **Trusted demonstration reader, `list`, `arrays`, and `video` commands only:** all IDs 0000–0099 were listed; all numerical arrays and all original wrist MP4 streams were requested. Arrays contained only robot `state`, `actions`, and `timestamps`. All numerical trajectories, initial wrist images, and sampled contact/end views informed corpus analysis and selection. Selected sequences were examined at approach, grasp, all three closing/reopening phases, and final hold. Original base/random_camera videos for 0000, 0039 and 0050 were additionally examined to check lifting and retention. No original Zarr was opened.
- **Pinned robot README and `mjcf/panda_allegro_copy.xml`, commit `8d23b0fab23b17a58c4b55f3942e17013aaf8267`:** used only for the wrist camera's relative transform and field of view, attachment-site orientation, hand joint ordering and ranges, and the distinction between camera/attachment/site frames. No task scene was inferred from the robot XML. The README mentions `input/robot.json`, which was not present; the provided task JSON, MJCF and numerical traces supplied the layouts instead.

Retained numerical examples are **0000, 0006, 0011, 0014, 0017, 0025, 0028, 0039, 0050, 0068, 0079 and 0086**. The `trajectories/` files preserve their exact released numerical arrays, recompressed without extra fields. Each entry in index.json records the trusted reader's original numerical and wrist-video SHA-256 digests. Selection means visual evidence of retained tool and three motions at inspected frames; it is not an evaluator success label.

Reference JPEGs are labeled frame samples decoded from those released wrist streams. `references/overview.jpg` derives from the original 0039 base video, SHA-256 `5ec6f3b04e8c7700d5e06d7297abee20d5ae19e383183092724b946c6ca878d9`. `references/initial_atlas.jpg` contains cropped initial wrist views. `vision.npz` contains a small grayscale pivot patch and a circular interior mask derived from 0000's initial wrist frame. They are image references for ordinary normalized template correlation, not learned weights.

Source pivot XYZ coordinates were reconstructed from the selected streams' pre-contact wrist views and their public robot poses. Optical-flow predictions followed by dark-disk ellipse refinement supplied image correspondences; geometric reprojection fitting supplied XYZ. Fits use 29–57 unoccluded, post-settling frames per retained example and approximately 0.09–0.46 pixel RMS residuals. Residuals establish consistency with the camera model, not ground-truth object accuracy. Earlier unrestricted tracking drifted near occlusion/image borders; those correspondences were excluded. Initial-frame planar XY anchors serve only the less reliable single-view fallback.

`policy.py` contains newly written geometric vision, motion interpolation, example retrieval, rigid pose retargeting and an optional thumb-cycle primitive. These derivations use no parameter training. NumPy, SciPy, OpenCV, Pillow and PyAV available in the preparation environment were used for numerical/image processing. No full videos, robot meshes or scratch analysis are required at test time. Numerical and released-image checks are recorded in VALIDATION.md; no task rollout was possible during preparation.
