No external websites, papers, benchmark descriptions or hosted research sources were used. No other learned model or agent was invoked. All task information came from the supplied task metadata, released demonstrations and pinned robot reference.

Sources and uses:

- **Provided task metadata (`task.json`).** Established the instruction “Fold the glasses and place them into the case,” task name `fold_glasses`, `rand_full` regime, single-arm layout, camera mapping and 30-Hz control rate.
- **Trusted demonstration reader: `list`, `arrays`, `video` only.** Read numerical `state`, `actions`, `timestamps` for all released IDs **0000–0099**. Sampled eight wrist RGB frames per demonstration, with denser frame inspection for selected examples. Used these for task sequencing, variability, timing, action/state conventions and measured tracking statistics. Inspected selected base-camera sequences **0000, 0012, 0015, 0042, 0079, 0080, 0094** to resolve contact and placement. The summary is in [data/corpus_summary.json](data/corpus_summary.json).
- **Retained demonstration examples 0094, 0015, 0042.** [data/manifest.json](data/manifest.json) maps the retained numerical arrays and RGB-derived reference images to original demo IDs, cameras and frame numbers, with original numerical-file hashes. The retained NPZs contain only the three released numerical fields. Phase labels, hand-posture names and the approximate 0094 scene geometry are our annotations/reconstructions, not privileged labels. The image sheets pair base RGB above wrist RGB; full-size images are explicitly named `wrist`.
- **Provided pinned robot README and authoritative `panda_allegro_copy.xml` MJCF**, upstream commit `8d23b0fab23b17a58c4b55f3942e17013aaf8267`. Used only for robot hand ordering, joint axes/limits, fingertip geometry, attachment-site transform and wrist camera pose/FOV. These constants are incorporated into [geometry.py](geometry.py). The supplementary URDF was not needed. The README mentions a `robot.json` that was absent; layouts were taken from the supplied task metadata and cross-checked against the released array shapes and robot sensors.

Processing used the preinstalled Python, NumPy, SciPy, OpenCV, PyAV and Pillow packages. MuJoCo loaded only the provided robot model for an offline forward-kinematics cross-check; no task scene or task simulation was loaded. Classical feature matching and ray geometry were used for approximate visual reconstruction; no learned weights were fitted or updated.

The preparation did not access original Zarr data, a privileged state suffix, evaluator source, hidden seeds, test results or future episodes. No scoring or success threshold was inferred from unavailable internals. Validation described in [VALIDATION.md](VALIDATION.md) concerns the package and robot geometry only.
