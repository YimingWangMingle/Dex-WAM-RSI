All task knowledge comes from the user-provided release. **No external websites, papers, benchmark descriptions, other learned models, or other agents were used.** No weights were updated.

- `input/task.json`: task instruction, bimanual robot type, `rand_full` regime, 30 Hz rate, action/state layouts, camera mapping, and count of 100 demonstrations.
- Trusted demonstration reader, `list`: IDs `0000`–`0099`, step counts, and available RGB streams. The first inspection command was the requested reader `list` command.
- Trusted reader, `arrays 0000` through `arrays 0099`: only released `state`, `actions`, and `timestamps`. Used all 46,255 steps for motion/hand-pattern analysis, timing checks, reference selection, and the trajectory bank. The package retains the original actions and sampled robot proprioception; no task/object state was present in these arrays.
- Trusted reader, `video ID random_camera`, `video ID wrist_left`, and `video ID wrist_right` for all 100 IDs: decoded with PyAV. Initial/final base views were inspected across the entire corpus; wrist frames supported grasp/press study, initial landmark inspection, geometric calibration, and logo tracking. Selected detailed sequences, including the shortest and longest examples, informed limitations and preferred references. Original MP4s are not copied into the package.
- `input/robot_reference/README.md` and pinned `mjcf/panda_allegro_bimanual.xml`, `mjcf/panda_allegro_left.xml`, `mjcf/panda_allegro_right.xml`, upstream commit `8d23b0fab23b17a58c4b55f3942e17013aaf8267`: robot attachment/site/camera transforms, camera field of view, hand joint chains, and fingertip collision geometry. Used only as robot definitions. `hand_geometry.json` is a compact extraction of those hand chains. The left public hand ordering was additionally checked against released RGB.

Derived, approximate scene measurements in `constants.json` and `catalog.json` come from RGB plus public robot poses: ray triangulation of stationary features, threshold/ellipse localization of the lens-barrel patch, and red-logo tracking. They are not privileged scene observations. `camera_shift_from_0000` refers to a visual landmark displacement; it is not a measured object-state field. The aim pivot is a heuristic from the left finger geometry. The geometric plan adaptations and recovery suggestions are authored procedures inferred from demonstrations.

Validation performed during preparation:

- Preserved all 100 original action arrays exactly; checked dimensions, finite values, and 1/30-second timestamp spacing.
- Visually checked the strongest oval detection in every released initial left-wrist frame (100/100 on the intended patch; threshold support at least six). This is a training-image appearance check, not a test-episode result.
- Initial left/right images provided an unambiguous automatic camera/target estimate for 93/100 demonstrations. Seven require a second view or manual logo choice. Initial automatic red-point estimates differed from the multi-view reference by median 0.26 mm, maximum 8.9 mm; these estimates share the inferred plane prior and are not independent ground truth.
- Checked all 17 preferred references reproduce their original arrays exactly when the input scene equals their own reference. Checked 68 geometric adaptations for dimensions, finite commands, identical hand trajectories, preserved start actions, and the intended aiming rotation. Checked rigid corrections preserve the relative wrist transform.
- Ran localization, automatic reference selection, plan generation, chunk serialization, and scouting-array generation from a separate read-only copy of the package in a fresh directory. Checked local documentation links and the absence of runtime paths to original inputs or scratch files. Exact measured states are retained for the saved preferred-reference image frames.
- Robot-camera projection agreed with stationary matched image features (a representative static-feature pair had median reprojection error about 0.10 pixel). The visual oval-centre triangulation is less precise, at a few pixels across views.

No simulator rollout, test seed, test episode, evaluator, scoring implementation, or test result was accessed. Numerical/geometric validation does not establish task success. The original demonstrations, source videos, scratch analyses, and their file paths are not runtime dependencies of this package.
