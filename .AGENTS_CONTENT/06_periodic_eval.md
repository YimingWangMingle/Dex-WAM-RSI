# 周期性评测（periodic_eval/）

每 `periodic_eval.interval_steps` 步、**每 rank 各评一个固定 batch**（size = `training.batch_size // 4`，最小 1，可 `periodic_eval.batch_size` 显式覆盖），每轮内容与配比逐轮一致。逻辑全在 `periodic_eval/`；`train/train.py` 与 `train_debug/micro_train.py` 只调 `build_periodic_evaluator(...)` + `evaluator.maybe_run(model, global_step)` + `close()`。

- **评测集**：各源 holdout（`eval_pool`，无则回退 `pool`）+ 可选 EWMBenchmark（集群 `/data/chen.liao/EWMBenchmark`，63 条视频-only：PNG 帧+指令文本，无 action/state GT——借用机器人名 `agibot-a2-d` + 零 state 占位锚点，action 只存预测不对比）。**GT 视频统一等效 5fps（20260820 起）**：indexed 源由 eval_pool ranges 的 video_stride 布局保证（30fps 源 ratio 6、10Hz 源 ratio 2）；EWMBenchmark 原生 30fps，GT 按 `native_fps`（默认 30）→`gt_fps`（默认 5）抽帧（stride=max(1,round(native/gt))=6 抽 1，YAML `periodic_eval.ewmbenchmark.native_fps/gt_fps` 可覆盖），与 pred 48 帧逐帧对齐（此前取连续 48 帧 = 30fps，GT 只覆盖 1.6s 与 pred 9.6s 错位）；ewmbenchmark spec 带 `native_fps`/`gt_fps` 键，旧连续帧缓存 spec_key 失效自动重备（indexed 缓存不受影响）。**action 是否预测由 batch 声明驱动（20260819 起）**：`inference_step(predict_action=...)`（True=零 state 也强制预测、False=强制跳过、None="全 0 state=action 缺失"启发式——训练与默认推理行为不变）；runner 按缓存 meta 的 `state_action_policies` 通用映射（`placeholder`→True、`absent`/`none`→False、其余/未声明→None），EWMBenchmark batch 显式声明 `placeholder`（spec 同步带该键使旧缓存失效重备）——修复前零 state 被启发式判为 action 缺失，预测被吞、action 曲线数据不落盘；未声明且 state 全 0 的源按源去重 warning 一次防静默回归。各源权重（`periodic_eval.source_weights`，缺省 = 训练权重 + ewmbenchmark 0.25）经 largest-remainder 把 world_size 个 rank 确定性分配到 (源, shard_ordinal)，纯函数无通信。
- **indexed 源 batch 构成（跨 episode 多样化）**：`data_prepare.create_diverse_eval_batch` 用固定 seed 洗牌 holdout episode 顺序，按 shard_ordinal 步进取 `batch_size` 条**不同 episode** 各一个窗口拼批（episode 数不足时回绕、重复 episode 换窗口）——避免原按 episode 组批（`EpisodeGroupedBatchSampler`）导致的整批同一任务、长 episode（如 agibot_beta）独占大量 shard 的问题。
- **启动时后台预解码缓存**（训练前台零解码）：batch 固定 ⇒ Trainer 构造时缓存（`<cache_dir>/<spec_key>/`：tensors.pt uint8 + pils/*.png + meta.json + manifest.json）缺失时每 rank 拉起 CPU-only 子进程 `python -m periodic_eval.prepare`（`CUDA_VISIBLE_DEVICES=""`）取单源 eval 取数（`fetch_indexed_eval_batch`，seed 固定/epoch=0）确定第 k 个 batch 落盘。spec_key = 源定义+文件 size/mtime+形状+种子参数 sha256（含 `batch_size` 与 `spec_version`），manifest 另存完整内容 sha256 ⇒ **同配置新任务直接命中缓存、启动零解码**。生产 `cache_dir` 在共享存储（`/data/chen.liao/thinkerwm-pretrain/periodic_eval_cache`）。
- **一轮 eval**（`maybe_run`）：缓存未就绪则跳过本轮记事件（集合通信仍全员参与，不死锁）；就绪则按 (源, shard, seed) 定种子（跨轮一致、与训练 RNG 隔离）→ `inference_step`（eval + no_grad）→ 可选旁路 VLM greedy `generate` 出文本（**模型内 VLM 纯编码不生成 token**；micro 替身无 generate 时降级 null）→ 指标 → 媒体写 monitor run_dir `eval/step_xxx/rankR/sampleK/` → `all_gather_object` 汇聚 → rank0 追加 `run_dir/eval/*.jsonl` → keep_rounds 清理。任何失败只记日志/事件，不拖挂训练。
- **monitor 展示**：server `STREAM_NAMES` 含 `"eval"`，`GET /api/runs/{id}/file?path=<rel>` 供 run 目录内媒体（resolve+包含检查防逃逸）；前端「eval 评估」tab 按轮次/源浏览样本卡片。eval 轮耗时记 `step_record["periodic_eval_seconds"]`，按源指标以 `periodic_eval_*` 键并入 step_record。
- **action 曲线/指标显示空间（20260817 起）**：命中统一布局的机器人，action 曲线（见下条）、action 指标与 meta.json `eef_display` 统一在 **EEF 规范显示空间**——每臂 3pos+6rot+1gripper（单臂源 10 维、双臂源 20 维），由 `periodic_eval.config.build_eef_display_layouts(config)` 从 `dataset.robot_names` 的 `unified_dim_map`/`unified_rot_groups`/`eef_relative` + `dataset.unified_bands` 推导槽位，`render.actions_to_eef_display` 把 raw local（GT 与 pred 同为反归一化绝对位姿）转显示空间：pos/gripper 直通、本地旋转表示经 `models.action_repr` 转 6D（**quat 符号翻转在此消除**，q/−q 同一矩阵；delta 源如 libero 标签带 `(delta)`）。无夹爪本体的 gripper 槽为 NaN（曲线留空、指标跳过、meta 中为 null，标签带 `(n/a)`）。action 指标同在该空间统计：`action_mse`（仅有效维，**数值与此前 raw 空间不可直接比**）+ 分组键 `action_mse_pos`/`action_mse_rot6`/`action_mse_gripper`（无有效维不产出）。未命中布局的机器人（无 dim_map 等）回退原生逐维显示与旧指标行为。meta.json 仍保留 raw local 的 `gt_actions`/`predicted_actions`/`action_dim_labels`（调试用），并新增 `action_display_space`（`eef_v1`/`raw_local`）与 `eef_display.labels/gt/pred`。
- **action 曲线 = 网页端渲染（20260820 起）**：训练侧不再生成 `actions.png`（`render.save_actions_plot` 已删，periodic_eval 不再依赖 matplotlib），仅记录数据（meta.json `eef_display.labels/gt/pred` + raw `gt_actions/predicted_actions`）；monitor 前端 `web/actionplot.js` 从 meta.json 取数据 canvas 逐维绘制（4 列网格、gt 实线/pred 虚线、IntersectionObserver 懒加载、旧 run 回退显示历史 actions.png）。**y 范围按维度语义 band 固定**（用户拍板：不同 dim 可不同、同一 dim 跨 eps/数据集必须一致）：`DEFAULT_BAND_RANGES` = pos [-4,4] / rot6 [-1.1,1.1] / gripper [-2,2] / other [-2,2]（按 stage2_20260818_v1 生产 eval 数据 |v| 分位数定：pos p99.9≈3.7、rot6 max=1.0、gripper p99≈1.5；robotmind ark 系夹爪 ±32 等超出部分裁剪不显示），eval tab 工具栏「y 轴范围」按 band 自定义覆盖（localStorage 持久化、应用后全部图表重绘）。**点击缩略图进交互大图弹层（20260821 起，`ActionPlot.openInteractive`，复用 eval 弹层壳 + `LineChart`）**：联动十字线 + tooltip/状态栏读数、共享 x 视窗滚轮缩放/拖拽平移/双击复位、GT/Pred 显隐、y band/自适应、维度过滤、单击 cell 进单维聚焦（←/→ 切换维度、Esc 返回网格）、CSV/PNG 导出；y 编辑器改动经 `redrawAll` 同步重绘。**网格用比缩略图更大的渲染参数（11px 深色标签/1.8px 线宽/cell 128px，drawCell opts 参数化，缩略图保持 9px/1.2px 默认）**；查看器网格与 `BaseChart`（charts.js）均有 `matchMedia(resolution)` dpr 变化监听——跨屏拖动/系统缩放后按新 dpr 重建位图，避免旧位图拉伸变模糊。
- **action 曲线维度名**：前端曲线子图标题与 meta.json `action_dim_labels` 用 `periodic_eval.config.build_action_dim_labels(config)` 生成的逐维语义标签（来自 `dataset.robot_names` 的 `unified_dim_map`/`unified_rot_groups` + `dataset.unified_bands`，如 `eef_left_pos[0]`/`eef_left_gripper`，摘除维标 `dim{k}(dropped)`）；无 band 注册/无配置时回退 `dim {k}`。标签保持 ASCII。
- **VLM 输入与训练一致**：`model.unified_vlm_task_prompt: true` 时用 `build_vlm_task_message` 重建消息。
- micro 冒烟：`configs/micro_train_debug.yaml` 的 `periodic_eval` 节（interval 4、4 步去噪、ewmbenchmark 关闭、缓存 `outputs/periodic_eval_cache/`）。
